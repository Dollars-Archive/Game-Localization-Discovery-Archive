# 후보 목록 삭제·복구

## 사용하는 방법

1. 사이트 우측 ⚙에서 기존 찜 편집 열쇠를 등록한다. 이미 등록한 기기는 추가 설정 없이 사용한다.
2. 소유자 계정 및 저장소 쓰기 권한 확인이 완료되면 게임의 `삭제` 버튼이 나타난다.
3. 게임명·기종을 확인한 뒤 삭제 확인창을 승인한다.
4. 저장 완료 후 공개 후보 목록·검색·내 목록·찜·착수 그룹·비교에서 해당 게임이 빠진다.
5. 다른 PC·폰에서는 페이지를 새로고침하여 같은 상태를 확인한다.
6. 되돌리려면 상단 `삭제한 게임`을 열고 `복구`를 누른다.

삭제는 공개 웹 목록에서 제외하는 기능이다. 게임 상세 문서와 원본 후보 표는 남아 있으며 직접 링크로 열 수 있다.
기존 찜·메모·순서도 보존하므로 복구하면 다시 표시된다. 별 버튼의 찜 해제와는 다른 동작이다.
웹 후보 수는 삭제를 반영하며, 저장소 README의 원본 집계 숫자를 매번 수정하지 않는다.

## 권한·저장

- 열쇠가 없거나 Dollars-Archive 소유자 확인을 통과하지 못하면 읽기 전용이다.
- 사용자 ID `314692476`과 저장소 쓰기 권한을 GitHub API로 확인한다. 실제 저장 권한은 GitHub가 검증한다.
- 별도 서버 정책은 없으므로 저장소에 쓰기 권한이 있는 다른 자격 증명으로 GitHub 파일을 직접 수정하는 것까지 막는 기능은 아니다.
- 삭제·복구는 `watchlist-data` 브랜치의 `docs/data/excluded-games.json`에만 기록한다. 파일은 첫 저장 때 생성된다.
- 찜 파일 `docs/data/watchlist.json`은 수정하지 않아 예전 클라이언트와 서로 덮어쓰지 않는다.
- 동일한 문서 경로로 새로 조사해도 삭제 기록을 자동으로 지우지 않는다. 소유자가 직접 복구한다.
- 삭제 파일 변경은 main에 커밋하지 않아 Pages를 다시 빌드하지 않는다.
- 토큰을 문서·삭제 데이터·로그·URL에 기록하지 않는다.
- 동기화 실패 시 마지막 캐시 또는 원본 목록이라는 안내가 나온다. 최신 삭제 목록을 확인할 때까지 삭제·복구 쓰기는 막는다.
- 저장 실패 시 목록은 그대로 유지하며 실패 안내를 표시한다. 권한이나 네트워크를 확인한 뒤 재시도한다.

## 운영 변경 규칙

- 새 기종에도 문서 경로 기반 키를 사용한다. 삭제 기록을 제목만으로 매칭하지 않는다.
- 후보 상세 문서나 원본 목록 행을 삭제 버튼 처리 중 제거하지 않는다.
- 후보·검색·집계·비교·내 목록에 같은 삭제 필터를 적용한다.
- 삭제 상태를 찜 JSON에 합치거나 기존 삭제 기록을 초기화하지 않는다.
- 409 및 최초 파일 생성 경쟁 시 최신 데이터에 이번 게임의 동작만 병합한다. 다른 게임의 삭제·복구는 보존한다.
- 테스트에는 가짜 게임과 API 응답을 사용한다. 실제 운영 게임을 임의 삭제하지 않는다.
